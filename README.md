# WeatherWidget

Замена штатного пассажирского виджета даты, времени и погоды в Flyme Auto.

- Дата и время отображаются в часовом поясе, выбранном в настройках Android.
- В России доступны три источника прогноза погоды — Гидрометцентр, Open-Meteo и Яндекс Погода. Для Яндекс Погоды нужен личный API-ключ.

Проверено на `LYNK FlymeAuto 900 2.3.1.5`.

На каждой из двух карточек видны температура и значок погоды. У Open-Meteo и Яндекса первая карточка показывает прогноз на текущий час, а вторая — на 1, 3, 6 или 12 часов вперёд (по умолчанию — на 3 часа). Переключатель «Прогноз» показывает или скрывает вторую карточку. У Гидрометцентра днём первым идёт дневной прогноз, ночью — ночной. Подписи уточняют время или дату, например `23:00 / 2:00 +1` или `ночь 17→18 / день 18`. День начинается в 08:00, ночь — в 20:00. Нажмите на шестерёнку, чтобы выбрать источник и город или включить автолокацию. Кнопка ⓘ открывает окно с версией виджета, временем последнего успешного обновления прогноза и ссылкой на исходный код. При открытии настроек виджет загружает каталог городов, если кэша ещё нет или он старше суток. Гидрометцентр и Open-Meteo работают без ключа.

Приложение заменяет штатный AppWidget через отдельный resource overlay (RRO).

Overlay перекрывает ресурс `com.flyme.auto.launcher:xml/widget_profiles`, из которого лаунчер читает состав и размещение виджетов. Скрипт извлекает этот XML из локального APK лаунчера и в пассажирской секции погоды (`displayType="psd"`, `widgetDisplay="weather"`) заменяет `widgetPackageName` с `com.flyme.auto.weather` на `me.elizarov.weather`, а `widgetClassName` с `com.flyme.auto.weather.module.ipcservice.appwidget.OrdinaryAppWidgetProvider` на `me.elizarov.weather.WeatherWidgetProvider`. Остальные записи и параметры сохраняются. В результате лаунчер сам размещает наш AppWidget в штатном погодном блоке; APK лаунчера не изменяется.

## Сборка

Нужны JDK 17+, Python 3.9+, Android SDK Platform 36 и Build Tools 36.0.0. Gradle wrapper включён в проект. Укажите `JAVA_HOME` и `ANDROID_HOME`, если они ещё не настроены; в скриптах на macOS используется SDK из `~/Library/Android/sdk`.

Из корня проекта, после подключения ADB:

```sh
export ANDROID_SERIAL=DEVICE_IP:5555
python3 tools/pull-assets.py --apks-only
./tools/build.sh
```

Получатся `widget/build/outputs/apk/release/widget-release.apk` и `overlay/build/weather-overlay.apk`.
Скрипт собирает подписанные release APK, инструментальные тесты для release и запускает Lint. Приложение и overlay подписываются одним постоянным release-ключом.

При первом запуске создаются `signing/release.keystore` и `signing/release.properties`. Последующие сборки используют тот же ключ. Сохраните резервную копию всего каталога `signing/`: он содержит закрытый ключ и пароли, исключён из Git и нужен для выпуска совместимых обновлений. Отдельная подготовка ключа: `python3 tools/signing.py init`.

Для последующих сборок только приложения: `./gradlew :widget:assembleRelease`.

## Локальные ресурсы машины

`pull-assets.py --apks-only` получает пути пакетов через Android Package Manager и скачивает `AutoLauncher.apk` и `AutoWeather.apk` в `local-assets/`. Можно указать устройство явно: `--serial DEVICE_SERIAL`. Скрипт только читает файлы через ADB; root для скачивания не нужен.

При сборке `prepare-assets.py` использует `aapt2` из Android SDK: извлекает основу макета даты/часов и разделитель из APK погоды, добавляет наш интерфейс прогноза и создаёт overlay из профиля виджетов APK лаунчера. В нём меняются пакет и класс погодного AppWidget; остальные записи сохраняются. Сначала используются ожидаемые имена ресурсов, затем подходящие варианты из таблицы ресурсов APK. Результат записывается в `local-assets/generated/`. Проверок SHA или номера прошивки нет; ошибка возвращается, если необходимые ресурсы извлечь не удалось.

Если APK уже сохранены локально, их можно передать без подключения к машине:

```sh
./tools/build.sh /path/to/AutoLauncher.apk /path/to/AutoWeather.apk
```

Без флагов `python3 tools/pull-assets.py` скачивает и APK, и шрифты. Весь каталог `local-assets/`, включая оригинальные XML, шрифты, APK и сгенерированные ресурсы, исключён из Git. В репозитории хранятся наш код, дополнения интерфейса, официальные погодные иконки Яндекса и скрипты обработки ресурсов.

## Первая установка — нужен root

Нужны доступный `su 0` и перемонтируемый `/system`. В командах `--user current` обозначает текущего пользователя Android; его ID можно узнать через `adb shell am get-current-user`.

```sh
adb install --no-incremental -r --user current widget/build/outputs/apk/release/widget-release.apk
adb push overlay/build/weather-overlay.apk /data/local/tmp/weather-overlay.apk
adb push tools/stage-overlay.sh /data/local/tmp/stage-overlay.sh
adb shell su 0 sh /data/local/tmp/stage-overlay.sh
```

Скрипт размещает overlay в `/system/app/WeatherWidgetOverlay/`, выставляет права и SELinux-контекст и возвращает `/system` в режим чтения.

Для первого обнаружения системного пакета нужен перезапуск Android framework. Команда ниже прервёт интерфейс и ADB/Wi-Fi; выполняйте её только на стоящей машине, когда готовы к этому:

```sh
adb shell su 0 setprop ctl.restart zygote
```

После перезапуска заново подключитесь по ADB. IP-адрес Wi-Fi машины может измениться: в этом случае обновите `ANDROID_SERIAL` командой `export ANDROID_SERIAL=DEVICE_IP:5555`, указав новый адрес. Затем включите overlay и перезапустите лаунчер, чтобы он перечитал список виджетов:

```sh
adb shell pm install-existing --user current me.elizarov.weather.overlay
adb shell cmd overlay enable --user current me.elizarov.weather.overlay
adb shell 'su 0 kill -TERM $(pidof com.flyme.auto.launcher)'
```

## Разрешения и использование

Для автоматической локации выдайте разрешения и включите геолокацию Android:

```sh
adb shell pm grant --user current me.elizarov.weather android.permission.ACCESS_COARSE_LOCATION
adb shell pm grant --user current me.elizarov.weather android.permission.ACCESS_FINE_LOCATION
adb shell pm grant --user current me.elizarov.weather android.permission.ACCESS_BACKGROUND_LOCATION
```

Выберите город в настройках виджета. При включённой автолокации он используется как резервный: виджет определяет место по последней известной позиции Android возрастом до двух часов, а если её нет — использует выбранный город. При выключенной автолокации выбранный город используется всегда.

Прогноз запрашивается при запуске, если нет подходящего кэша за текущий час, затем на границах часов Android: после загрузки в 12:45 следующая запланирована на 13:00. Кэш и время загрузки сохраняются между запусками процесса и Android. Изменение города или перемещение минимум на 10 км также могут потребовать новых данных. Повторное нажатие на прогноз использует подходящий кэш; после ошибки автоматическая повторная попытка планируется на следующий час. Если машина спит или нет сети, запрос выполняется после пробуждения/восстановления сети. Запросить проверку через ADB:

```sh
adb shell am broadcast --user current -a me.elizarov.weather.REFRESH_WEATHER -n me.elizarov.weather/.WeatherWidgetProvider
```

Ответы источников хранятся раздельно. После переключения обратно виджет может использовать подходящий кэш для текущего места.

## Сетевые запросы и ссылки

Размеры указаны для тела одного ответа без сжатия по контрольным запросам. Размер прогноза Яндекса взят из сохранённого ответа на 48 часов.

### Общие для всех источников

| Адрес | Зачем и когда | Размер ответа |
| --- | --- | --- |
| `GET https://meteoinfo.ru/forecasts` | Начальная страница каталога городов — при открытии настроек, если кэша нет или он старше суток. | ≈126 кБ |
| `GET https://meteoinfo.ru/forecasts/{path}` | Страницы стран, регионов и городов для обновления каталога. Страница выбранного города также нужна для определения ID станции при ручной локации или использовании резервного города. ID кэшируется на сутки. | ≈125 кБ на страницу |

Ссылка в окне «О приложении» открывает исходный код во внешнем браузере. [Репозиторий на GitHub](https://github.com/elizarov/flyme_weather_widget)

Для всех трёх источников виджет берёт из APK оригинальные светлые и тёмные иконки Яндекса. Происхождение иконок и условия их использования описаны в [THIRD_PARTY.md](THIRD_PARTY.md).

### Прогноз Гидрометцентра

| Адрес | Зачем и когда | Размер ответа |
| --- | --- | --- |
| `POST https://meteoinfo.ru/hmc-output/forecast/tab_0.php` | Подбор станции по округлённым координатам при первом определении позиции и при перемещении минимум на 10 км. Неудачные попытки могут повторяться. | ≈7 кБ |
| `GET https://meteoinfo.ru/rss/forecasts/index.php?s={station}` | Температуры и даты прогноза по ID станции — в начале часа либо при смене станции. Подходящий кэш текущего часа используется повторно. | ≈2,5 кБ |
| `GET https://meteoinfo.ru/forecasts/{path}` | Дневные и ночные условия для иконок загружаются со страницы прогноза, адрес которой указан в RSS. | ≈125 кБ |

Нажатие на подпись источника или стрелку ↗ открывает страницу прогноза во встроенном браузере. Крестик справа вверху закрывает окно с любой страницы.

### Координаты для Open-Meteo и Яндекс Погоды

| Адрес | Зачем и когда | Размер ответа |
| --- | --- | --- |
| `GET https://oscar.wmo.int/surface/rest/api/search/station?wigosId=0-20000-0-{station}` | Координаты одной станции для ручного или резервного города. ВМО получает только ID станции. Запрос выполняется при отсутствии записи или когда прошло 30 дней с последней проверки. | ≈0,8–1,3 кБ |

Координаты каждой найденной станции сохраняются отдельно в SQLite. По истечении 30 дней виджет перепроверяет их при следующем использовании этой станции. Если ВМО не ответила или не вернула подходящие координаты, виджет продолжает использовать предыдущую точку и перепроверит её через 30 дней. APK содержит только исходный ID и координаты Москвы для первого запуска.

### Прогноз Open-Meteo

Выберите «Open-Meteo» в строке «Источник». Один запрос возвращает почасовой прогноз на 48 часов по округлённым координатам. Карточки показывают температуру на текущий и выбранный будущий час по времени Android. Код погоды ВМО и признак дня или ночи определяют иконку для каждого часа. В начале следующего часа обе карточки сразу используют сохранённые данные, пока загружается свежий прогноз.

| Адрес | Зачем и когда | Размер ответа |
| --- | --- | --- |
| `GET https://api.open-meteo.com/v1/forecast` | При смене часа или точки. Параметры — `latitude`, `longitude`, `hourly=temperature_2m,weather_code,is_day`, `forecast_hours=48`, `timeformat=unixtime`, `timezone=GMT`. | ≈1,3 кБ |

Подпись «Данные Open-Meteo ↗» открывает график на странице Open-Meteo для той же точки. Бесплатный API предназначен для некоммерческого использования. Данные предоставляются по CC BY 4.0. Виджет округляет температуру до целых градусов. [Условия Open-Meteo](https://open-meteo.com/en/terms) · [Лицензия данных](https://creativecommons.org/licenses/by/4.0/)

### Прогноз Яндекс Погоды

| Адрес | Зачем и когда | Размер ответа |
| --- | --- | --- |
| `POST https://api.weather.yandex.ru/graphql/query` | Текущие условия и почасовой прогноз на два дня. Запрос выполняется в начале часа либо при смене точки. Личный ключ передаётся в заголовке `X-Yandex-Weather-Key`. | ≈5,3 кБ |

Подпись источника и стрелка ↗ открывают прогноз во встроенном браузере по адресу `https://yandex.ru/pogoda/?lat=…&lon=…`. Для ссылки используются те же округлённые координаты, что и для запроса прогноза. Ссылка получения личного ключа также открывается в браузере. [Кабинет Яндекс Погоды](https://yandex.ru/pogoda/b2b/console/smarthome)

## API Яндекс Погоды

В настройках выберите «Источник → Яндекс Погода». Ссылка «Получить личный ключ» открывает [личный кабинет](https://yandex.ru/pogoda/b2b/console/smarthome) во встроенном браузере. Вставьте ключ в скрытое поле и нажмите «Сохранить ключ». Кнопка «Удалить ключ» справа от поля сразу стирает сохранённый ключ с устройства. Приложение Яндекс Погоды устанавливать не нужно. Ключ хранится только в закрытых настройках Android, не попадает в URL, журналы или резервное копирование приложения. Файлы `yandex_weather_key.txt` исключены из Git; не публикуйте личный ключ и не используйте один общий ключ в распространяемом APK.

Личный тариф предназначен для личного некоммерческого использования. Ограничения тарифа применяет сам API согласно [условиям Яндекса](https://yandex.ru/legal/apib2c_weather_agreement/ru/). Приложение обновляет прогноз в начале часа или при смене точки. Если API отклонил запрос из-за лимита, виджет продолжает использовать доступный прогноз из кэша.

Один API-ответ содержит почасовые данные на сегодня и завтра, поэтому обе карточки обновляются одним запросом. При смене часа подписи и значения выбираются из кэша сразу, параллельно планируется получение свежего прогноза. Если нужного часа в кэше нет, температура показывается как `—`.

## Использование координат

Автолокация по умолчанию выключена. При её включении и наличии разрешений приложение берёт последнюю известную позицию Android возрастом до двух часов, без отдельного запуска GPS. Перед отправкой погодному сервису широта и долгота округляются до узла сетки с шагом примерно **5 км**; исходные точные координаты в интернет не отправляются. В режиме Гидрометцентра округлённые координаты передаются в POST-запросе подбора станции. Для Open-Meteo и Яндекс Погоды округлённая точка передаётся непосредственно выбранному сервису. Для ручного или резервного города виджет использует координаты станции из ВМО и округляет их по той же сетке. Поиск по каталогу и ввод текста не отправляют запросов в Open-Meteo или Яндекс.

Последняя известная позиция проверяется при минутном обновлении виджета и перед запросом прогноза. После успешного определения новая точка отправляется только при удалении минимум на **10 км** от предыдущей точки выбора: у Гидрометцентра меняется подобранная станция, у Open-Meteo и Яндекса — округлённая точка прогноза. Для точного расчёта расстояния в закрытых данных приложения сохраняются последние точки выбора станции и попытки обновления — без истории перемещений. Старый кэш без округления заменяется после первого успешного определения по новой схеме. Если позиция или подбор станции недоступны, используется выбранный резервный город. Для автоматической точки Open-Meteo и Яндекса виджет показывает «Рядом с вами».

## Обновление и откат

После сборки новой версии, когда overlay уже зарегистрирован и включён:

```sh
./tools/update.sh "$ANDROID_SERIAL"
```

Обновляется только приложение, Android и лаунчер не перезапускаются. Overlay при обычных обновлениях менять не требуется.

Отключение замены: `./tools/rollback.sh "$ANDROID_SERIAL"`. Штатный виджет вернётся при следующем перезапуске лаунчера. Системный overlay можно оставить выключенным.

## Локальная проверка

Устройство провайдеров, кэша прогнозов и общего каталога городов описано в [архитектуре виджета](ARCHITECTURE.md).

Проверка скриптов на синтетических данных без подключения к машине:

```sh
python3 -m unittest discover -s tools/tests -v
```

Укажите серийный номер запущенного эмулятора в переменной `EMULATOR_SERIAL`:

```sh
./tools/test-local.sh "$EMULATOR_SERIAL"
```

По умолчанию тестируется release APK: регистрация AppWidget, RemoteViews, геометрия, часовые пояса, прогноз и кэш. Скрипт принимает только эмулятор.

Для разработки и предпросмотра соберите debug-вариант:

```sh
./gradlew -PtestBuildType=debug :widget:assembleDebug :widget:assembleDebugAndroidTest
./tools/test-local.sh "$EMULATOR_SERIAL" debug
```

В debug доступны `PreviewActivity`, галерея иконок и `OverlayProbeReceiver` для диагностики ресурсов лаунчера и состояния погоды. Эти классы и локальные шрифты предпросмотра не включаются в release. Release содержит рабочий AppWidget и настройки.

Для предпросмотра поверх реального экрана Flyme можно подготовить локальную подложку из полного PNG-снимка 5120×1600, затем пересобрать debug APK:

```sh
python3 tools/prepare-preview.py /path/to/flyme-screen.png
./gradlew -PtestBuildType=debug :widget:assembleDebug
adb -s "$EMULATOR_SERIAL" install -r widget/build/outputs/apk/debug/widget-debug.apk
./tools/preview.sh "$EMULATOR_SERIAL"
```

Для запуска без Vulkan можно использовать: `./tools/run-emulator.sh YOUR_AVD -port 5560`. Имена установленных AVD: `"$ANDROID_HOME/emulator/emulator" -list-avds`. Скрипт сохраняет данные Android и отключает диалоги/отправку crash reports только для этого запуска.

Подложка сохраняется в `local-assets/res/drawable-nodpi/preview_flyme_screen.png`, исключена из Git и доступна только в debug. Предпросмотр открывается полноэкранно; активные часы, прогноз и настройки размещаются поверх снимка. Без локальной подложки используется однотонный фон. Встроенный браузер и настройки открываются отдельными задачами, поэтому закрытие их окон не закрывает предпросмотр.


Автономная проверка парсинга API, почасового ограничителя, смены часов и изоляции кэшей (без ключа и без HTTP-запросов):

```sh
adb -s "$EMULATOR_SERIAL" shell am instrument -w -e api local me.elizarov.weather.test/me.elizarov.weather.WidgetSmoke
```

### Шрифты для эмулятора

Чтобы предпросмотр использовал шрифт цифр с машины, отдельно выполните:

```sh
python3 tools/pull-assets.py --fonts-only
```

Скрипт ищет конфигурацию и файлы шрифтов в `system`, `product`, `system_ext` и `vendor` и сохраняет доступные шрифты в `local-assets/fonts/`. Если конфигурация недоступна, проверяются ожидаемые пути к обычному начертанию `LynkcoDisplay`. Оно также копируется в `local-assets/res/font/lynkco_display.otf` для debug-сборки; отсутствие дополнительных начертаний не мешает скачиванию. Пути сохраняются в локальном manifest. Без этих шрифтов предпросмотр использует стандартный шрифт Android; на машине используются системные шрифты.
